# Vocab Hub Project Conventions

## Commands
- **Dev server:** `npx expo start` (press `a` for Android / `i` for iOS, or scan the QR code in Expo Go). For a debug build, JS is served live from Metro — a JS-only change never needs a rebuild, just a cold relaunch of the app (`am force-stop` + relaunch on Android) to pick it up.
- **Type check** (the only static check in this repo — there is no lint config and no test runner): `npx tsc --noEmit`
- **Native rebuild** — only needed after adding/removing a native dependency or changing an `app.json` plugin:
  ```
  npx expo prebuild --platform android
  cd android && ./gradlew assembleDebug
  ```
- **Release APK:** `cd android && ./gradlew assembleRelease` → `android/app/build/outputs/apk/release/app-release.apk`. There is no dedicated release-signing config; it's signed with the debug keystore (fine for ad-hoc test-team distribution, not Play Store ready).
- **`android/` is gitignored and fully generated by `expo prebuild`** — never hand-edit files under it; all native config belongs in `app.json` plugins. If a Gradle build fails referencing a resource from a module that's no longer a dependency, that means `android/` has drifted out of sync with `app.json`/`package.json` (e.g. edited independently in an earlier session) — regenerate it with `npx expo prebuild --platform android --clean` rather than patching the generated files.
- **Seed a test device:** `./scripts/seed-device.sh [-s <serial>]` pushes `test-data/vocab-hub-seed.db` (232 words, every arcade game unlocked, onboarding dismissed) directly into the app sandbox — use this instead of walking the CSV import through the UI. It re-stamps `created_at` so the collection reads as added today (`--keep-timestamps` opts out), and only works on a **debug** build, since `run-as` is refused for a non-debuggable package. `node scripts/build-seed-db.mjs` regenerates the snapshot from the CSV after a schema migration or a CSV edit.
- No Jest/CI. Verification is manual: on-device walkthrough, direct SQLite inspection, `adb logcat`. `test-data/` also keeps the raw 232-word CSV (importable via Settings → Import & export → Import words (CSV)) for exercising the import path itself.

## Architecture
- **Boot sequence:** `index.ts` calls `initPlaybackNotification()` *before* `registerRootComponent(App)` — Android delivers notification-press events (Travel Mode's lock-screen transport controls) to a background handler that must already be registered when they arrive. `App.tsx` nests `ThemeProvider` → `PaperProvider` → `NavigationContainer` → `DialogProvider` → `UnlockProvider` around a 5-tab bottom navigator (Home/Add/Travel/Quiz/Settings). The onboarding carousel gates the entire tab navigator until `settings.onboardingComplete` is set — no tab is reachable before that.
- **Data layer:** a single WatermelonDB model, `Word` (`src/db/models/Word.ts`), over SQLite/JSI. Screens never one-shot fetch; they subscribe through `observe()`-based hooks in `src/hooks.ts` (`useAllWords`, `useGameUnlockStatus`, `useStreakManager`, etc.), so the UI updates reactively as records change anywhere in the app. `Word`'s WatermelonDB decorators are applied **manually** via a `applyDecorators()` helper instead of `@text()`/`@date` syntax — Babel's decorator transform conflicts with `babel-preset-expo` on SDK 57. Read the comment block at the top of that file before touching it; don't "simplify" it back to `@`-decorator syntax.
- **No separate tables for prefs/progress** — daily goal, theme, travel/quiz settings, game best-scores, and `streak.state` all live as JSON strings in WatermelonDB's `local_storage` key-value table (`src/db/settings.ts`; full key list in `docs/OVERVIEW.md` §3). The adapter double-JSON-encodes string values on write — relevant if you ever inspect/seed this table via raw SQL instead of the app's own getters/setters.
- **Streak engine** (`src/lib/streakEngine.ts`): day completion is always *derived* from each word's `created_at`, never stored — only the non-derivable overlay (freeze inventory, protected days, an open repair challenge, celebrated milestones) is persisted as the single `streak.state` key. This derive-don't-store split is why streak logic has never required a schema migration, and why the Home summary card and the Streak detail screen can't disagree with each other.
- **Dictionary auto-fill** (`src/api/dictionary.ts`): queries the Free Dictionary API, Wiktionary, and Datamuse in parallel (8s timeout each) and merges results with dictionary → Wiktionary → Datamuse priority for synonyms/antonyms. Layman explanation and example sentence have no free source and are generated locally by heuristic when the APIs don't supply one. Every populated field carries a `FieldSource` tag so the Add Word screen can badge sourced vs. locally-generated values.
- **Game Arcade unlocks** are a single ordered array, `GAMES`, in `src/lib/games.ts` (key/threshold/mechanic per game) — `useGameUnlockStatus()` derives locked/unlocked state live from the total word count via `observeCount()`. Adding a game or changing a threshold is a one-line array edit, not a screen change.
- **Travel Mode categories** (`src/lib/travelCategories.ts`) are a single array of `{key, label, match(word, now)}` predicates — same one-entry-to-extend shape as the Game Arcade list.

## App Requirements
1. **Daily Practice Goal:** Default is 5 words/day, but MUST be user-configurable in settings.
2. **Word Data Schema:**
   - Word, Pronunciation, Audio URL
   - Primary Meaning
   - Exactly 2 Synonyms, Exactly 2 Antonyms
   - Contextual Example Sentence
   - Layman's Terms Explanation (Optional string)
   - Word Origin (Optional string)
   - Part of Speech, Word Forms (grammatical variants)
   - Created At (timestamp), Difficulty Level, Practice Status
3. **Audio / Travel Mode:** Continuous back-to-back playback of words + meanings with pause intervals, TTS pitch/speed control, and background audio readiness. The playlist is picked from predefined categories (`src/lib/travelCategories.ts` — All / Recent / Needs practice / Mastered / Challenging), with per-word exclusions as refinement; add a category by appending one entry to `TRAVEL_CATEGORIES`.
4. **Testing Engine:** Dynamic quizzes (Flashcards, Multiple Choice, Fill-in-the-Blanks) based on user's learned vocabulary pool.
5. **Word Management:** Delete-word with confirmation warning; CSV import/export (bulk add/backup) matched by header name, with a downloadable template.
6. **Game Arcade:** 5 vocabulary mini-games (Vocab Millionaire, Memory Match, Scrabble, Crossword, Spelling Bee — `src/screens/games/`) that unlock progressively as the user's word count grows (thresholds in `src/lib/games.ts`). Each has SFX (tap/success/error/fanfare) toggleable in Settings.
7. **Streak System:** Forgiving daily-goal streak (`src/lib/streakEngine.ts`) with a 2-hour post-midnight grace period, 1 free freeze per 10-day run, a 48-hour repair challenge on an unprotected break, and milestone celebrations at 7/14/30/50/100 days. Day completion is always derived from `created_at`; only the freeze/repair/milestone overlay is persisted (`streak.state` in `src/db/settings.ts`).
8. **Legal & Privacy:** Terms of Service and Privacy Policy viewable in-app from Settings → About & Legal (`src/screens/legal/LegalViewerScreen.tsx`). The text lives in `src/screens/legal/policies.ts` and mirrors `docs/legal/*.md` — **edit both**, as Metro cannot bundle `.md` as source.

## Code Standards
- Use TypeScript for strict type checking.
- Keep UI modern, vibrant, and clean with intuitive animations. Give Claude design freedom for layout, themes, and micro-interactions.
- Do not use paid APIs or third-party paid services.
- App display name is "Vocab Hub" (rebranded from "AptitudeWords"), but the native package/bundle ID (`com.anonymous.AptitudeWords`) and `app.json`'s `slug` (`AptitudeWords`) are intentionally unchanged, to avoid breaking the native project identity. Do not "fix" this mismatch.
- Theme is 3-way (`light`/`dark`/`system`, see `ThemeContext.tsx`), not a boolean toggle.
- Use `useAppDialogs()` (`src/ui/AppDialogs.tsx`) for confirmations and toasts instead of `Alert.alert`.

## Tech Stack & Core Libraries
- **Framework:** React Native with Expo (Managed Workflow)
- **Database:** WatermelonDB (Offline-first, reactive persistent storage)
- **TTS:** react-native-tts (Offline native text-to-speech)
- **Background audio:** `react-native-notify-kit` — Android `mediaPlayback` foreground service + notification transport controls for Travel Mode (`src/lib/playbackNotification.ts`). `android/` is gitignored/generated, so native config goes in `app.json` plugins only.
- **Audio SFX:** expo-audio (native SFX playback for the Game Arcade, `src/lib/sfx.ts`)
- **APIs (all free & keyless):** Free Dictionary API (primary), Wiktionary MediaWiki `action=parse` (etymology + curated syn/ant), Datamuse (syn/ant backfill) — all in `src/api/dictionary.ts`
- **Styling & UI:** React Native Paper + Lucide Icons + Expo Linear Gradient
- **Legal docs:** `react-native-markdown-display` renders the Terms/Privacy viewer (`src/screens/legal/`). It needs the `punycode` package installed explicitly — its `markdown-it@10` dependency requires that Node builtin, which React Native does not ship.

## Documentation
